# 长期记忆

> 对标：Octop 的 `infra/agents/memory`（backend / slim / slim_control）
> 状态：**已实现**

## 1. 要解决什么

会话之间是断的：用户上次说"我们用深色主题""回答尽量短""这个项目不引入新依赖"，
新会话里 Agent 完全不知道。上下文摘要只在**同一个会话内**生效，跨不过会话边界。

长期记忆补这块：把值得记住的事实存下来，每次运行按相关性挑几条注入。

## 2. 检索用词法，不用向量

这是刻意的取舍。接向量检索就要接 embedding 服务（本地模型下载或云 API），
对自托管是一个不小的额外依赖；而"用户偏好、项目约定、已确认结论"这类记忆通常
带明确关键词。

实现：英文按词切，中文按**字符二元组 + 单字**切，按命中比例打分（默认阈值 0.12）。

**边界**：「用户喜欢深色主题」和「他要暗色 UI」不会互相命中——这是词法召回，
不是语义检索。需要语义时把 `search_memories` 换成向量实现即可，接口不用动。

## 3. 谁会'被记住'

- **显式写入**：`POST /memories`，人或外部系统直接记一条；
- **按需提炼**：`POST /conversations/{id}/memories/distill`，把一段会话交给模型
  提炼 0-N 条（模型返回 JSON）；解析失败就返回空列表，不硬失败。

**没有做自动提炼。** 自动提炼会让每轮对话多一次模型调用，成本翻倍且容易记进噪音。
需要时显式调一次即可。

## 4. 注入规则

- 只注入与**本次用户输入**相关的记忆（`memory_min_score` 阈值）；
- 单次最多 `MEMORY_INJECT_LIMIT` 条（默认 5）；
- 注入位置：system prompt 末尾的 `[相关记忆]` 块；
- Agent 级记忆 + 租户级记忆（`agent_id` 为空）都参与，别的 Agent 的记忆不会被注入；
- 检索任何异常都降级为"没有记忆"，绝不影响对话。

## 5. 实现位置

| 关注点 | 位置 |

| 分词、打分、召回、提炼 | `backend/app/services/memory.py` |

## 6. 测试

- 分词与打分：中文二元组、英文词、无关文本得 0；
- CRUD：创建/列表（含 `q` 过滤）/删除/审计/权限/跨租户不可见；
- 注入：相关记忆出现在 system prompt；无关输入不注入；别的 Agent 的记忆不注入；
- 提炼：正常 JSON 落库、非 JSON 容忍为空、内容太少返回 422、条数上限生效。

## 7. 明确不做

- 不做向量检索（见上文取舍）；
- 不做自动提炼；
- 不做记忆的版本/冲突合并（同一事实重复写入会并存，靠人工或后续去重）；
- 不做记忆衰减/过期。
